# 2026-09-08 环境搭建

## 做了什么

从 CUDA 11.7 升级到 12.8，Nsight 工具链一并更新。

## 遇到的问题

**问题：nvcc 11.7 无法为 Blackwell 编译**

现象：系统 Toolkit 是 2022 年的 11.7，而 RTX PRO 5000 Blackwell 是 sm_120，
Blackwell 编译支持从 CUDA 12.8 才开始。

为什么之前没发现：ComfyUI 用的是 PyTorch 自带的 cu128 运行时，
和系统 Toolkit 是两套独立的东西，所以一直能正常出图。

**关键认知：**
- 驱动 = 全局唯一，所有程序共用
- 系统 CUDA Toolkit = nvcc 编译用，PyTorch 不碰
- PyTorch 自带 CUDA 运行时 = 装在 venv 里的 .so

## 怎么解决的

选择 apt 方式（便于长期维护），但需防止 NVIDIA 源覆盖驱动：

1. 加 NVIDIA 源（cuda-keyring）
2. **加源后立刻写 pin 规则**，禁止从 NVIDIA 源安装驱动类包
   （`/etc/apt/preferences.d/nvidia-driver-protect`，Pin-Priority: -1）
3. `apt-mark hold` 锁住现有驱动包，双保险
4. `--dry-run` 预演，确认无 Remv、无 nvidia-driver/dkms 安装
5. `sudo apt-get install cuda-toolkit-12-8`
6. 环境变量指向 `/usr/local/cuda-12.8`（不动 `/usr/local/cuda` 软链接）

**验证 pin 生效**：NVIDIA 源里有更新的 580.178.04，
`apt-cache policy` 显示其优先级为 -1，确认被拦截。

## 踩坑记录

- `apt install cuda` 或 `cuda-12-8` 会连驱动一起装，必须用 `cuda-toolkit-12-8`
- 装的是 open kernel module 驱动（nvidia-driver-580-open），
  残留一个版本落后的 nvidia-dkms-580，暂不处理
- `cuda-driver-dev-12-8` 名字带 driver，但只是驱动 API 头文件，不是内核模块

## 验收结果

- 驱动：580.173.02（未变动）✅
- nvcc：12.8.93 ✅
- nsys：2024.6.2 / ncu：2025.1.1 ✅
- `nvcc -arch=sm_120` 编译通过 ✅
- ComfyUI：`torch.cuda.is_available()` = True, capability = (12, 0) ✅
